# formal-coverage v1.7.3

Rust doc comments no longer inflate measured code sizes. The Rust lexer turns
`///`, `//!`, `/** */` and `/*! */` into `doc` attribute tokens; previous releases
counted those token spans as code. SLoC now skips `#` (optionally followed by `!`)
and a bracket group beginning with the identifier `doc`. Explicit attributes such
as `#[doc(hidden)]`, `#[doc = "text"]` and `#![doc = include_str!("guide.md")]`
are excluded too.

This changes measured sizes, including coverage denominators and status-weighted
line totals. Percentages may rise or fall according to which units lose doc
lines. No tier rule, receipt grammar or threshold changed. Other attributes
continue counting, string literals retain their contents, and a line shared by
a doc attribute and real code still counts once. Malformed-file fallback sizing
still counts every nonblank line, including comments.

The same filter applies to inline Verus ghost ownership, so doc-only lines do not
inflate inline proof sizes or affect mixed runtime/ghost ownership. Dependency
and trusted-item sizing inherit the correction through the shared SLoC counter.

A report-only replay of Bertie at `f646099`, using the existing fresh F* receipt
and the CI command, changed first-party security runtime size from **6,382 to
5,818** lines. An independent source scanner counted exactly **564** removed
doc-only lines. All **469** unit tiers stayed unchanged, and no unit grew;
**223** unit sizes changed. The `server` function fell from **73 to 20** lines.
See the [complete comparison](../dev/v173/compare.md), including all changed
units, headline percentages and input/artifact hashes.

Cargo package metadata and its lock entry are now `1.7.3`; the v1.7.1/v1.7.2
release commits had retained the older `1.5.0` package version.
