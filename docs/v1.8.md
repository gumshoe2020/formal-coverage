# formal-coverage v1.8

hax/F* projects now have a proof-to-code ratio. The denominator includes
`proven` plus `proven-extracted` runtime SLoC, reported separately. Bounded
runtime keeps its existing treatment. The numerator includes standalone and
inline proof, strictly verified hand-written patch additions, and configured
hand-written F* proof files. Models are reported as trusted assumptions and
never enter the ratio; generated extraction, ProVerif and SSProve are excluded.

An exact-path whitelist measures hax annotations after doc exclusion, including
crate aliases. In default `separate` mode, annotation-only lines move from
runtime to inline proof; mixed lines stay runtime. In `runtime` mode they stay
runtime and contribute no annotation proof cost. `assume` keeps its escape
classification. Unknown hax paths are listed for review and never counted.

Optional `[fstar.proof]` configuration lists patch, proof-file and model globs.
Missing matches are errors. Patch targets must match strictly verified modules
in an accepted receipt; excluded hunks retain their target and reason. Proof
files require receipt-matching bytes and cannot be generated extraction or
models. Without accepted evidence, patch and file proof cost is zero.

Bertie at `f646099` has **350** annotation proof SLoC and **696** remaining
proven-extracted runtime SLoC: ratio **0.503**, below its unchanged 5–15 range.
Its legacy patch targets `Bertie.*`, while the receipt names `Bertie_tls.*`:
all **105** hunks count zero. The models contribute a separate **18** SLoC.
No tier, evidence acceptance, receipt grammar or threshold changed.

Cargo metadata is `1.8.0`. JSON report schema is 4 because default hax runtime
sizes and the ratio denominator change; config remains schema 2/3. Cross-schema
baseline gates require the existing `--allow-schema-change` acknowledgement.
See [README](../README.md) for configuration and the
[full paired comparison](../dev/v18/compare.md) for Bertie, scratch-server,
Vest, fixture checks, every changed size, and exact rerun commands.

## v1.8.1: cfg(hax) proof code

Extraction-only items whose own or enclosing cfg attributes imply hax now count
as standalone proof in both ghost modes. The shared cfg algebra accepts hax,
all with a hax-implying arm, and any only when every arm implies hax. Negation,
cfg_attr conditions and similarly named features do not qualify. This applies
only within existing first-party hax projects; gated use items add no units.
Test classification takes precedence: existing test units retain their category,
status and size. Credited proof units become verified, while other statuses
remain unchanged.

Within runtime functions, cfg(hax) statements and blocks move to inline proof
in separate mode and stay runtime in runtime mode. Shared runtime lines remain
runtime and annotation overlaps count once. Test units never contribute inline
proof. Annotations inside standalone proof units count only there. New ratio components `fstar_cfg_hax_sloc` and
`fstar_cfg_hax_inline_sloc` expose these subsets at every scope.

Bertie f646099: 18 units / 197 standalone SLoC. Four test helpers under
cfg(all(test,hax)) remain test/unverified with their old sizes (57 SLoC total).
There are 57 inline cfg lines, 13 overlapping annotation lines.
Separate mode: 312 inline, 509 total proof, 549 extracted runtime / 5,309
security runtime SLoC, ratio 0.927, still below the unchanged 5–15 range.
The no-patches config gives identical figures. Legacy patch proof remains zero;
models remain 18 trusted-assumption SLoC. Cargo metadata is 1.8.1; schema stays 4
with the two additive component fields. Receipt/evidence/threshold rules and
all existing Verus/control figures remain unchanged. See the
[paired replay](../dev/v181/compare.md) for both modes, every unit/size change,
identity checks, independent source counts and rerun commands.
