# PLAN-RELEASE: make formal-coverage ready to publish (v1.4.1)

This plan is authoritative for this pass. The repository is about to become public under the MIT
license. An independent acceptance check of v1.4 (2026-10-29) confirmed every proof number, but
found doc claims that understate trust/escape reliance, stale statements, and evidence that
outsiders cannot reproduce. This pass fixes those. It changes no measurement rule and must not
change any published proof percentage.

## Grounded facts (checked 2026-10-29)
- `main` @ `a07ac51`. `cargo test --frozen` (50 pass, 1 ignored), clippy `-D warnings`, `fmt
  --check` and `git diff --check` pass in a clean clone.
- Recomputing the three survey reports (Vest, Anvil, Firecracker M2b) from retained receipts with a
  clean-clone release binary gives byte-identical `report.json`/`report.md`, apart from the cargo-home
  path prefix.
- `docs/scratch-server/` holds about 28 MB of tracked files: 13 full per-branch JSON reports
  (0.5–3.6 MB each) plus small Verus logs, `*.v1.json` and `runs.json`. These are generated by
  `scripts/dogfood.py`.
- `scripts/check_survey.py` needs untracked `logs/`, `runs/` and `../coverage-survey` clones, and
  asserts the SHA-256 of the local `target/release/formal-coverage`. A fresh build hashes
  differently, so the check fails anywhere but the author's tree.
- Absolute paths (`<local-path>`) appear about 640 times in tracked files, mostly inside generated
  reports and plans. `scripts/dogfood.py` hard-codes the scratch-server path.

## Non-negotiables
- Never change a measurement rule, the receipt grammar, or a threshold to move a number. If a fix
  would change any proven / proven-bounded percentage, stop that item and log it in NOTES.md.
- Third-party code (Verus, Kani, dependency builds) runs only inside Docker, as in v1.4: pinned
  image IDs, `--network none` for verifier runs, and never mount `$HOME`, `~/.ssh`, `~/.cargo` or the
  Docker socket. No host installs.
- scratch-server is read-only. Measure it only through `git archive` of these pinned commits, never
  its working tree, because another agent is editing it concurrently:
  `<notes>/acceptance/scratch-server-branch-tips-2026-10-29.txt`
  (branch name and commit per line).
- Commit only in this repository, one commit per milestone (plus separate commits for any genuine
  bug fix, each with a regression test). Do not push. Do not rewrite history; history cleanup
  happens later, outside this pass.
- Redirect every build/verifier log to a file and read only `tail -n 30` or grep.

### M4: reproducible evidence
- Regenerate the per-branch scratch-server reports with the current tool at the pinned commits
  (above), with output paths relative to the repo (no absolute paths in any generated file).
- Split the evidence:
  - **In git** (small, needed to read the results): `docs/scratch-server.md` summary table,
    `runs.json`, the Verus receipts/logs, `*.v1.json`, `docs/survey/*`, and `runs/v1.4` manifests,
    summaries and receipts under about 1 MB each.
  - **Release bundle** (everything else the checkers need): the full per-branch JSON reports, the
    Firecracker `m2b/` logs, the Anvil fresh logs, and the `logs/v1.1-c-*` files.
    `scripts/make-evidence-bundle.sh` writes `../release/formal-coverage-evidence-v1.4.1.tar.zst`
    (outside the repo) plus a SHA-256 file. Bundle paths are relative to the repo root, so
    extracting it in a checkout restores what the checkers need. `git rm` the bundled files from
    `docs/scratch-server/` and add them to `.gitignore`.
- Checkers (`check_survey.py`, `check_dogfood.py`, `check_perf.py`) and `dogfood.py`:
  - take paths from arguments or the environment, with repo-relative defaults; no hard-coded
    `<local-path>`. The scratch-server path becomes `--scratch-server PATH` (default `../scratch-server`).
  - Replace the release-binary SHA-256 assertion with a check that the report's recorded tool
    commit / source hash matches the checkout. A fresh clean build must pass.
  - If the bundle is absent, fail with one clear line naming the bundle and how to fetch it.
- docs/evidence.md: a "Reproduce the numbers" section that walks an outsider through cloning,
  downloading the bundle from the GitHub release, verifying its SHA-256, extracting it, building,
  and running the checkers. Say which checks need Docker and which run offline from receipts.
- Acceptance: in a fresh `git clone` under `$TMPDIR` with the bundle extracted, `cargo build
  --release --frozen` and all three checkers pass. Without the bundle they fail with the
  one-line message. The tracked tree is under 5 MB (`git ls-files -z | xargs -0 du -ch | tail -1`).
