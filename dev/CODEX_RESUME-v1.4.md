## M2b: Kani receipts with experimental features (Andrew's decision)

The grammar stays closed. It gets bigger, but it must not accept anything that weakens Kani's checks. Change the Kani branch in `src/evidence.rs` (around the `command.len() != 7` check) to accept a command when all of these hold:
- It starts with `cargo kani` and contains exactly one `--harness <ID>`, and `receipt.harnesses == [ID]`. Still one harness per serial log. Reject `--workspace`, `-j`, `--jobs`, more than one `--harness`, and `--harness` patterns that could match more than one harness.
- Each `-Z` value is from this allowlist: `unstable-options`, `stubbing`, `function-contracts`, `restrict-vtable`. Any other `-Z` value is rejected.
- Other flags are from this allowlist: `--output-format regular|terse` (either `--output-format X` or `--output-format=X`), `--harness-timeout <dur>`, `--package <name>` / `-p <name>`, `--unwind <N>` with N > 0. Anything else is rejected, including `--no-unwinding-checks`, `--no-assertion-reachability-checks`, `--no-default-checks`, `--no-overflow-checks`, `--no-memory-safety-checks`, `--default-unwind`, `--cbmc-args`, `--enable-unstable` and `--concrete-playback`.
- Result parsing doesn't change: one `Checking harness ID` line matching the command, exactly one `VERIFICATION:- SUCCESSFUL`, and no FAILED or error lines. Confirm this works on the terse logs in `runs/v1.4/firecracker/`.
- Unwind bound, in this order: `--unwind N` from the command, then `#[kani::unwind(N)]` on the harness in the hashed source, otherwise "Kani default: no unwind limit, unwinding assertions on". Every case still counts as `proven-bounded`, never unbounded proven. Remove the hard-coded `receipt.command[6]` index from the proof-scope string.
- Proof scope has to state what the features assume. For a harness with `#[kani::stub(A, B)]`, add "A replaced by stub B". For `#[kani::stub_verified(F)]`, add "F assumed to meet its contract". For `#[kani::proof_for_contract(F)]`, the scope is F's contract (requires/ensures), not F's whole behaviour. If `restrict-vtable` is on, add "dyn calls restricted to type-compatible vtable targets". Read the attributes from the hashed source, not from the log.
